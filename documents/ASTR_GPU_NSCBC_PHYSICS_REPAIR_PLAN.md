# GPU NSCBC 物理问题与修复计划

审计日期：2026-10-09。工作分支：`feature/gpu_dev`。

## 授权与正确性依据

本轮获准修复明确的物理问题，不再以复现旧 CPU 边界行为作为 GPU 正确性的判据。
采用守恒方程的 RHS 符号、局部几何法向特征方向、解析制造场和分区不变性验收。
旧 CPU 实现仅供追溯，不能作为存在相同缺陷时的参考真值。
本轮仅作本地有界测试，不操作 Git、远程作业或生产算例。

## 已知问题

下列位置以子程序名为准，行号可能随修复变化。表中记录修复前问题，最终状态与运行证据另列。

| 编号 | 位置 | 问题与触发条件 | 修复方向 |
|---|---|---|---|
| N1 | `src_gpu/boundary_gpu.cuf::nscbc_outflow_x_rhs_kernel` | x+ 法向差分产生正的通量导数，重构后却以正号加到 GPU 最终 RHS。GPU RK 更新不再作 CPU 的全局取负，因此与守恒方程的负散度相反。 | 用线性熵波实际核函数复现，再改为负散度装配。 |
| N2 | `src_gpu/mainloop_gpu.cuf` OpenShock NSCBC 显式重构分支 | x 边界核已加入 y/z 横向导数，随后全域 y/z 对流核又覆盖这些 x 边界节点。同一横向项有两个装配者。 | 为该路径限定后续横向核的有效 x 范围，保持物理边界横向项只加入一次。不得扩大到未审计路径。 |
| N3 | `src_gpu/boundary_gpu.cuf::gpu_nscbc_outflow_mach2` | 所有 rank 的局部 i=im 都参与出口最大法向 Mach 数归约，包含内部 MPI 接口。内部高速区可改变物理出口松弛。 | 仅物理 x+ 面所属 rank 提供局部最大值，其余 rank 仍参加集体通信，但不贡献接口值。 |
| N4 | `nscbc_inflow_x_rhs_kernel`，bc12 | 固定改写第 1--4 个特征，不按局部法向速度分类。超声速流入时漏掉第 5 个传入波；反向流动时可能改写传出波。松弛使用全域总 Mach 数，强切向速度也可使系数为负。 | 按 x- 面局部几何法向识别传入波，保持传出波；松弛率非负。完整目标使用已有全局远场状态。新增或不完整的倒流目标须明确拒绝或先获批。 |
| N5 | `nscbc_outflow_x_rhs_kernel`，bc22 | 无条件覆盖第 5 声波，超声速流出时仍干预传出波。`1-Mmax^2` 可为负；倒流时仅压力目标不足以约束全部传入波。 | 超声速流出保留内场特征，亚声速流出只处理传入声波，使用非负松弛率。未定义完整目标的倒流不得静默运行。 |
| N6 | `nscbc_farfield_y_upper_rhs_kernel` 的 compatibility 分支，bc52 | 无条件覆盖第 5 声波；超声速法向流出仍被改写，法向流入又未处理其他传入波。松弛系数也可能为负。 | 明确迁移至按局部法向分类的目标策略，或限制不受支持流态。不以流向 Mach 数代替顶面法向 Mach 数。 |

N1--N3 是装配/归属缺陷，不需要改变外部物理目标。
N4--N6 的特征方向判定是确定性修正；松弛强度、倒流完整状态和横向/黏性源项处理不能仅凭“CPU 原来如此”决定。
保留原强度常数不等于确认其为最佳物理参数。

### 已批准的 N4--N6 策略

用户已确认采用下列策略，不保留旧 CPU 的错误数值语义：

- bc12 使用已有全局 `roinf/uinf/vinf/winf/pinf` 构造完整守恒目标，只松弛局部传入波，松弛率为 `0.25 a/Lx`。
- bc22 亚声速流出只松弛传入声波。保留强度常数 `3.75`，使用局部法向 Mach 数，松弛率为 `3.75 (1-Mn^2) a/Lx`；按当前特征矩阵归一化压力偏差，使单独松弛项满足 `dp/dt=-K(p-p_target)`。超声速流出保留全部内场特征。倒流缺少完整目标，明确报错。
- bc52 compatibility 保留传出波。法向流入使用已有全局远场状态，只处理传入特征，强度为 `0.25 a/Ly`；亚声速流出仅松弛传入声波，使用局部 `Mn` 和 `0.25 (1-Mn^2) a/Ly`，并归一化压力偏差。
- 不修改已有 `incoming_only`、`sbli_shock`、`nonreflecting` 或 AIR5 特征顶面的源项策略。
- `compatibility` 名称仅为输入接口保留，不再承诺修复后的 GPU 与旧 CPU 结果逐值一致。

## 不能混为缺陷的能力限制

- bc52 `incoming_only` / `sbli_shock` 已按局部法向波速处理传入特征，系数非负。面上最大法向 Mach 数达到 1 时，部分亚声速流出点的目标松弛可能降为零；这属于目标保持策略的限制，不是负反馈符号错误。
- bc52 `nonreflecting` 及黏性变体有独立的几何法向和源项平衡实现。本轮保护这些路径，不把 LODI、目标松弛、源项平衡三种边界称为相同算法。
- AIR5 可选特征顶面保留横向、黏性、化学和 V-T 源项，是已批准的候选 A。不能因其不同于投影全部源项的候选 B 就判定错误。
- 当前 AIR5 特征顶面仅准入均匀笛卡尔网格；不能据此宣称曲线双温反应流 NSCBC 已完整支持。
- OpenSBLI 专用固定顶面虽使用 bc52 编号，但不是通用 NSCBC 验收。
- Ma12 流向速度不意味着顶面法向超声速。必须按实际几何法向速度判断。

### 本地验收与终止条件

- 制造场优先直接调用实际生产核函数，不以重新编写的算法副本代替。
- 解析 RHS、特征保留与分区场差最大绝对误差不超过 `2e-10`；分类与归属按逻辑精确检查。
- 覆盖亚/超声速流入、流出、掠流及强切向速度；不把未定义倒流目标作为已支持能力。
- 最小短步状态必须有限，密度、温度严格为正。Compute Sanitizer memcheck 零错误。
- 旧 CPU/GPU 对比若因本轮获准物理修正失效，须明确记录，不能放宽差值后称为通过。
- 不新增生产算例。出现需要新增物理目标、改变源项策略或验收含义的决策时停止相关项，提交人工决策。
- 所有获批修复及受影响检查通过后才完成 goal；部分通过不称为 NSCBC 全流态物理验收。

## 理论依据

亚声速流出有一个传入声波，超声速流出没有传入特征。约束应作用于传入信息，传出信息来自内场。
参见 [Grismer 与 Powers 的特征边界讨论](https://academicweb.nd.edu/~powers/paper.list/grismer.powers.shock.waves.pdf)。
多维反应流的横向、黏性和反应源项会改变特征边界的渐近状态，不能用一维压力松弛自动替代完整源项分析。
参见 [Yoo 与 Im, 2007](https://doi.org/10.1080/13647830600898995)。
曲线网格必须按几何法向构造特征，参见 [Kim 与 Lee, 2000](https://doi.org/10.2514/2.891)。

### 验收中发现的接入限制

新输出模块尚未注册 OpenShock，也尚未注册一般 bc12/bc22/bc52
输出/重启组合。即使关闭产品，原检查仍在初始化阶段拒绝，不能据此运行
旧 CPU/GPU 对比脚本。首次短测的 `final/` 和 `short_retry/` 保留了这一失败，
其中第一份还记录了测试配置误写 checkpoint `final_frame` 的语法错误。
这些失败发生在推进前，不作为数值误差或稳定性失败。

为本轮实际主循环验收，仅在 `BUILD_TESTING=ON` 构建内增加
`ASTR_VALIDATION_NSCBC_RK=1` 的有界入口：限定上述 64×8×8、
`maxstep=5`（含端点循环对应 6 次推进）、dt=`1e-5`、OpenShock、
12/22/周期组合、543e/643e、MP7 物理空间重构、`lfilter=f`/`diffterm=f`、
关闭 checkpoint/整场/切片/自适应输出且无重启目录。
`lfilter=f` 只关闭主滤波，NSCBC 出口自身的横向滤波仍按既有路径执行。
普通构建和生产输出准入不变，不开放任何新的检查点格式或续算保证。

NP=2 首次 memcheck 发现 HPC-X/UCC 在 MPI_Init 期间调用未建立上下文的
CUDA 探测 API，两个 rank 各报告 11 个错误。栈定位至
`ucc_mc_cuda_init` / `libuct_cuda`，在应用核函数执行前发生。
诊断环境沿用项目已有的 `OMPI_MCA_coll=^hcoll,ucc,cuda`，使用 host MPI
集体操作后重测零错误。未使用错误抑制文件或关闭应用核函数检查，
也不将该诊断环境作为 CUDA-aware MPI 的验收。

## 后续范围

- 本轮 N1--N6 修复不等于通用三维 NSCBC、长时声学反射率或生产 SBLI 已验收。
- 一般 NSCBC 工况的输出注册、精确续算、同相位输出和更广拓扑仍需独立推进。
  下节单独记录已注册 M12 剖面组合的有界输出与同拓扑续算，不扩大到其他组合。
- 原 CPU 的 12/22/52 compatibility 特征策略未改。旧 CPU 结果只能作差异诊断，不能再作为这些修复后的 GPU 分支的参考真值。
- bc22 倒流仍不受支持。将来若要支持，先定义完整外部状态及其源项耦合，不能取消当前拒绝检查就宣称支持。
- 原 `incoming_only`、`sbli_shock`、曲线非反射和 AIR5 特征顶面不借本轮扩大准入范围。已有 LODI 横向离散和源项策略也未重设计。
- 原接口的全域/面最大 Mach 数辅助计算仍保留，但不决定本轮修复分支的局部松弛率。bc22 为集体拒绝倒流增加了一次小整数归约。冗余归约清理属于后续性能工作，不能在本轮正确性结果中宣称通信优化。

### 接入与时序

- bc22 不再经过平板路径的 bc21 出口外推。
- x+ 横向滤波复用物理边界闭合，保留底壁节点；不读取未定义的物理面外 halo 来代替闭合。
- x+/y+ 交线上，x 边界装配 x 法向及 z 横向项，y 边界装配 y 法向项；z 项不重复装配。
- 联合路径复用真实第一 RK 阶段的准备，不恢复旧统计快照后重复执行壁面准备。
  两组同拓扑、同种子、每步三次壁面调用，保留相同随机吹吸抽样顺序。
- 新输出准入该组合的 GPU 基本切片/整场和同拓扑精确 checkpoint/重启。
  仍不准入 CPU 联合路径、重分区续算、平均量或自适应输出。具体重启证据见下节。
