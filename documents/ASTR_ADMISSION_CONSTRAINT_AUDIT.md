# ASTR 准入与约束审查记录

日期：2026-10-12。基准提交：`308b5f7`，审查包含当时未提交的工作区改动。
范围：`src/`、`src_gpu/`。方法：全目录检索，沿准入入口、调用方及状态消费者追踪，
使用 `avoid-overdefensive-programming` 区分必要保障、实现边界与历史验收白名单。
本记录不是新增物理工况的验收证明。未操作远程任务；未授权 Git 提交。

## 主要结论

主要问题是历史验收夹具变成生产准入，以及输出层反向限制求解器。
不能因此删除正性、有限性、模型有效域、同阶段状态、通信完成和检查点完整性检查。
放开不支持的配置不等于实现该能力。

## 验证与保留范围

实施应先复现针对性拒绝，再进行配置测试、CPU/CUDA 构建及短时真实续算/重分区。
构建、数值等价、物理验证、内存安全和性能分别记录，不互相替代。
本轮不更改离散格式、边界物理、模型有效域、默认 FP64 或显式同步策略。
未实施的网格、边界组合、跨后端精确续算和预览显示能力不因本轮改进自动获得准入。

### 实现细节

1. `check_capability` 仅对启用检查点或指定恢复目录的运行应用精确续算白名单。
   普通基本场输出按三维字段布局检查，派生量仍由其实现检查准入。
   `no-field-I/O` 覆盖先应用，再检查实际启用的产品。新配置必填和旧检查点拒绝不变。
2. M12 可只配置 `velocity_slice.image`，或启用其他合法非空子集。
   现有种子、设备后端及产品时钟规则不变。稀疏探针与每 50 步壁面 CSV 仍然保留。
3. `begin_insitu` 将已恢复的完整步编号传给 M12 诊断。
   从零启动保留 `probes.csv`；从 N 步恢复新建 `probes.from_stepNNNNNNNNNNNN.csv`，
   首次采样必须是 N+1。重复采样、跳步、文件冲突继续报错，不静默覆盖历史。
4. 通用重分区按分区覆盖、无重叠、方向约束和资源预算验证，不再按两 rank 截断。
   本轮矩阵为 32³ 周期滤波 TGV、CPU/GPU、NP=2→4、4→2、4x→4y，
   连续 12 步与 5+7 步对照。不累计原位统计、不渲染。
5. AIR5 配置在写入与比较时统一空白和既有默认值，布尔别名规范为 `on/off`。
   tau 的文本写法不参与比较，解析后的顶面松弛率等 40 个参数仍逐位比较。
   原始参数解析器继续拒绝非法输入；改变补偿、反应模式、限制器、顶面参数、资源或
   可能影响舍入顺序的物性复用/归约模式仍会拒绝精确续算。
6. 非反应 GPU 静态配置检查首次成功后缓存，`init_gpu` 重新初始化时失效。
   适用前提是当前静态网格和固定数值配置；控制器不修改这些配置。
   正性、有限性、CFL、保正预算与通信完成检查不缓存。
7. 配置日志保留请求值，新增 `ASTR_GPU_FLUX_PAIR_MODE_APPLIED` 表示实际路径。
   不支持融合时明确打印采用 `split` 的原因，维持原分派结果，不增加自动算法替代。
