# ASTR 多后端迁移方案

日期：2026-11-10。
状态：grill 设计决策及交叉审查的8项补充已确认；尚未启动主程序迁移。
源码核查基点：`feature/gpu_dev`，`93c5c6f5d6080f8e168062d66c397c188dfc0607`。

## 1. 目标与实施边界

逐步将现有 GPU 数值主体从 CUDA Fortran 迁移为共用 CUDA C++ 实现。
Fortran 保留输入、主流程、RK 阶段与物理流程调度、MPI 拓扑及输出职责。
NVIDIA 使用原生 CUDA 工具链；海光 DCU 首期使用 DTK GPUfusion 编译和
运行同一套 CUDA C++ 维护源。原生 HIP 留作后续扩展方向，不作为本轮生产
后端；不因 GPUfusion 可运行而宣称普通 AMD 平台已经适配。

本次访谈批准设计，不等于已经批准执行实现、构建、算例或平台提交。
本文件不创建或恢复 goal，不授权 Git 操作，不修改或替代其他尚在推进的
数值方法计划。开始实施时从 MB0 推进，平台操作另按第 10 节取得确认。

迁移现有数学定义与已验证行为，不同时更换物理模型、数值格式或边界条件。
发现 CPU 数值缺陷时，先提交证据由用户决定，不直接复制或修复。

## 4. 目标职责与数据接口

```text
Fortran
  输入、网格/拓扑与 MPI 生命周期、RK 阶段、物理流程、输出调度
                         |
                  ISO_C_BINDING / C ABI
                         |
C++ 设备执行层：每 rank 一个主机端管理对象
  流场与几何设备地址、按需工作区、流/事件、halo 缓冲与请求
                         |
            共用 CUDA C++ 数值计算主体
               /                         \
    NVIDIA 原生 CUDA              DCU DTK GPUfusion
```

### 4.1 所有权与数组布局

- 设备上下文是主机端管理对象，不是另一份流场。按现有功能条件分配数组，
  不因使用上下文就分配未启用的化学、统计或滤波工作区。
- Fortran 通过句柄按模块发起操作，不逐点跨语言调用。
- Fortran 内置数组第一下标连续，C/C++内置多维数组最后下标连续。
  Fortran 的 q(i,j,k,c)在 C++中等效按 [c][k][j][i]理解，不能直接改写为
  q[i][j][k][c]。扁平缓冲按现有下界和实际步幅索引，不强制转置。
- q、qrhs、qsave等分别保留其有效区和 halo 范围；不把所有数组统一扩大。
  默认单分量滤波及已有全变量可选方式按现有接口分阶段接入，不更改滤波公式。
- 字段视图明确设备地址、类型、范围和步幅。借用者不能释放资源，不能把
  设备地址通过普通主机数组映射后直接在 CPU 解引用。
- 重分配、缓冲角色变化或销毁后，原借用视图按约定失效；不承诺永久地址。
- 未来重布局、PCR 私有重排和工作区优化可独立推进，不改变权威变量的定义。

### 4.1.1 状态修改、刷新与消费

地址仍有效，不代表它保存的原始量、物性或梯度仍对应当前守恒状态。
按以下关系保持现有语义；表中“失效”是数据依赖说明，不要求新增通用版本号
系统、逐核状态检查或无条件全场重建。

| 状态修改 | 需要重新就绪的数据 | 消费者与发布时机 |
|---|---|---|
| 初始化上传或检查点恢复 | 按精确/非精确恢复合同恢复或重建原始量、halo及相应缓存 | 首次CFL、统计、边界或RHS使用之前；精确恢复不能被无条件重建破坏 |
| RK更新或物理边界修改q | 受影响的rho/vel/p/T、相关物性和导数，以及下次模板需要的halo | 按已有阶段顺序准备，在对应消费者流上建立依赖 |
| 显式/紧致滤波修改q | 按现有方向顺序准备周期数据和方向中间态；规定完成点刷新原始量及相关缓存 | 下一方向模板及滤波后RHS分别使用其约定状态；不把逐分量中间态作为完整新场发布 |
| 共享节点协调/平均 | 受影响的halo、原始量和物性；只刷新halo时不重复平均共享节点 | 后续模板与物性查询使用协调后的同一状态，保留现有最终halo刷新语义 |
| crashfix或保正修复改变状态 | 修复区域及后续模板受影响范围的数据 | 修复后的边界、通量和统计不能继续使用修复前缓存 |
| AIR5化学/输运更新 | q、补偿余量、T/Tv、组分、物性和子步历史按相应阶段合同关联 | MB8迁移时保持同状态物性复用及补偿生命周期，不能混用更新前后状态 |
| 完整步统计/输出/导出字段视图 | 消费字段对应当前完整步，且生产它的设备操作已就绪 | 未请求的派生量不为输出而额外计算；输出不得修改权威推进状态 |

具体刷新复用 `src_gpu/mainloop_gpu.cuf`、`src/mainloop.F90`、
`src_gpu/halo_exchange_gpu.cuf`及对应物性模块中已验证的顺序。只重建实际变化
且后续需要的数据，不因引入C++上下文而撤销已有的同状态缓存复用优化。

### 4.2 调度、同步与通信

- Fortran 保留 RK 和物理流程顺序；C++只组织被调用模块内部的设备操作。
  同流顺序、跨流事件与主机完成点共同保证数据就绪，不让调用顺序隐含地
  代替跨流依赖。
- 保留核启动错误检查，并在必要完成点检查执行错误。逐核同步仅作为显式
  调试模式；不能把取消同步解释为忽略错误。
- Fortran 决定何时开始和完成交换。C++管理打包、发送就绪、MPI请求、接收、
  解包及流依赖；begin不能等待整个交换结束才返回，end确保后续消费者可用。
- MPI 主线程在 GPU执行期间推进请求；不假设非阻塞MPI一定自动进展。
  不因设备计算在 C++内就新增通信线程或无条件要求 MPI_THREAD_MULTIPLE。
- 拓扑和通信域沿用现有 Fortran 职责，跨语言使用标准句柄转换，不直接重解释
  Fortran MPI句柄。设备指针也不能直接作为普通 Fortran c_ptr变量发送。
- 复用 ASTR 当前 halo 宽度、字段集合、共享节点处理、只刷新halo的语义及
  交换依赖。禁止照搬 OpenCFD 的 LAP、字段集合或全局静态资源结构。
- 单rank周期问题也要更新当前阶段的周期halo和重复端点；滤波后及滤波方向
  之间按现有模板刷新。该本地周期操作属于MB2，不等待MB3跨rank传输实现。
- 固定页主机中转与 GPU-aware MPI 均显式选择，不在运行失败后自动切换。
  新 C++首期中转路径不改变冻结实现的既有生产通信配置。
- GPU-aware 验证必须使用实际分配的 DCU 设备缓冲，不依据 cudaMalloc 的
  名称推断 MPI/UCX 已支持；不把 CUDA API兼容等同于网络栈兼容。

### 4.3 构建与源码组织

- 统一通过根 `CMakeLists.txt`构建。显式区分冻结 CUDA Fortran、新 C++/CUDA、
  新 C++/GPUfusion构建，不根据 PATH 中存在 hipcc/nvcc 自动选路。
- 当前 ASTR_WITH_CUDA 含有 CUDA Fortran及其他CUDA构建职责，不能仅将它
  设为开启就认定 DCU可用。具体新选项命名在实施时沿用项目约定。
- 每种构建使用独立目录和工具链环境，明确真实设备架构，不按兼容编译器
  的名称或 NVIDIA宏推断硬件能力。不在一个环境中任意混用 CUDA/HIP。
- 保留 `src/`及 `src_gpu/`布局，不先移动旧文件。新代码可在现有目录内
  按设备状态、流体、线性求解、通信及物性化学职责归组，避免每个核单独成文件。
- 保持 MPI、Fortran、C++和 HDF5 的 ABI/运行库组合一致；C ABI不暴露
  C++容器、对象布局或编译器私有数组描述符。
- 沿用 MPI前设备绑定等现有初始化职责。Fortran控制宏观生命周期，C++负责
  对应设备操作，不因上下文设计而错误推迟全部设备选择。
- 不因本地 CUDA 13.1可编译，就假定目标 DTK支持同一API、参数和语义。
  线程束掩码、shuffle及归约按真实32/64执行宽度设计，不默认依赖软件模拟32线程。

### 4.3.2 浮点编译语义

迁移时保留已有数值敏感例程的运算约束，不仅记录FP64和优化等级。
`src/CMakeLists.txt`当前为 `src/chemistry_filter_math.F90`及
`src/chemistry_filter_operator.F90`单独设置IEEE、禁融合和相关设备非规格化数
行为选项；新C++源文件不会自动继承这些Fortran源选项。

MB1登记现有专用选项及其保护的数学操作，MB8将相应要求落实到新例程，
并在相关补偿/滤波数学迁移前核对。GPUfusion/DCC使用经确认的等价设置，
不能照抄NVHPC标志后忽略编译器警告。检查生成的编译命令与实际算术结果，
区分主机和设备生效范围；不假定一个标志对所有精度有相同效果。

约束按例程或必要的独立源单元设置，不全局禁用普通核的FMA优化，也不为
通过误差门槛统一开启fast-math或重关联。专用选项不得在合并构建目标时丢失。

### 4.4 输出、统计和续算

- 沿用现有输入与完整步输出调度，不恢复旧controller或旧检查点格式。

## 6. 数值与恢复比较口径

- 同状态离散算子和同相位短窗物理节点场，按每个变量计算
  `E = max(abs(new-ref)) / max(1, max(abs(ref)))`，要求 E <= 2e-10。
  不只比较全场总和，也不以统计量接近替代逐场检查。
- 复制、索引、序列化以及约定的同环境精确恢复，要求逐值一致。
- 所比较状态应有限；首期TGV的rho、p、T为正。对照使用相同初始状态、
  参数和采样相位；必要时先锁定同一状态比较算子，避免轨迹差异混入分项误差。
- 严格短窗逐场对照使用已有固定步长输入，使各实现的时间步序列、步数、RK
  阶段和物理时刻一致；不新增步长回放、插值对齐或重算功能。
- 自动步长另在一个代表短窗中检查CFL归约、所选dt、增长约束及恢复控制状态，
  区分同状态控制器计算与各自推进轨迹。相同步数不自动等于相同物理时刻；
  若各自dt序列不同，不直接将场差判为离散算子误差，先分离控制与状态差异。
  无需在每个拓扑、精度和滤波组合重复这项控制器检查。
- CPU参考与旧GPU若分歧，先定位；不自动放宽阈值，不只选择更接近新实现者。
- 不将短窗阈值机械套用到长期湍流轨迹。长期统计、守恒、能谱或新边界物理
  验证在对应阶段确定，不为本次语言迁移重新穷举历史长算例。
- 自动步长沿用现有定义及输入控制，不在迁移中增加新的CFL项、回滚重算
  或改变增长限制。固定步长仅为对照测试选择，不改变自动步长的生产默认。
  短测的具体网格、步数及输入在执行阶段依物理尺度确定。

## 7. 代表矩阵与性能口径

- 本地NVIDIA覆盖NP=1/2；DCU计划NP=1/2/4，一rank一卡，实际资源条件
  执行前核对。NP=2覆盖x、y、z分解，NP=4选择如2x2x1的双方向分解。
- 先运行最小能分离问题的组件和短窗，再扩大矩阵；复用有效的已有参考。
  不把一组小型测试当成全部三方向耦合、多节点扩展或所有工况通过的证据。
- 未来全局PCR、复杂边界及AIR5各补必要代表组合，不从首期矩阵自动外推。
- 性能测试与短窗正确性测试区分规模。NVIDIA新旧比较保持硬件、数值设置、
  通信后端、步长控制模式和统计频率一致；记录实际物理时长、步数及dt范围，
  排除启动及大文件I/O，记录完整RK、通信等待和显存峰值，不只记录单核加速。
- 首期不要求固定提升百分比。明显回退需定位和说明；不混淆新实现的主机
  中转与旧实现设备直接通信造成的差异，也不将不同卡的时间差全部归因于代码。
- 不自设新增磁盘、显存或主机内存预算上限；具体作业资源依任务说明申请。
  不因该条而声称无视物理容量或平台调度要求。
