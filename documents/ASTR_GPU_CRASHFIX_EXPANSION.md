# GPU crashfix 扩展邻域修复

日期：2026-10-25。用户批准：单圈修复后仍非法时扩大平均范围，继续寻找合法修复结果。
本轮只改 GPU 非反应五变量恢复路径，不修改原 CPU crashfix、滤波、通量、时间步或 AIR5 模型。
仍由现有 `lcracon=t` 启用，默认关闭，没有新增运行开关。

## 实现

入口：`src_gpu/crashfix_gpu.cuf::repair_crashfix_state_gpu`。

1. 先执行原有 26 邻点、`k/j/i` 原位顺序平均。成功修复的 q 保持原数值路径。
2. 若任意 rank 仍有非法流体节点，各 rank 共同进入扩展恢复。
3. 使用 `exchange_field_halo_gpu` 只刷新 halo，不平均共享节点，避免把 NaN 传播到合法副本。
4. 先并行检查本 rank 和可访问面 halo 是否存在合法供体；若没有，不对每个坏点盲扫整个局部域。
5. 对剩余坏点逐层扫描索引立方壳，每层只访问新增位置。范围限制于实际局部数组、已刷新面 halo 和真实物理域；不读取未刷新对角 halo。
6. 仅使用有限、正密度且能重构出有限正压力、温度和内能的状态。平均用增量加权，避免先求和溢出。
7. 扩大后平均仍不合法时，最后尝试最近合法层的单点均值。不是注入指定自由流，也不截断负值。
8. 更新物性及 `crinod_d`。若还有坏点但本轮有修复进展，继续 halo 传播；没有任意重试上限。
9. 若全局本轮无进一步修复进展，明确报错退出。不能从没有合法供体的全坏状态中构造有依据的平均。

不新增整场工作数组、CPU 求解回调或整场主机传输。新增通信和搜索只在原单圈失败后执行。
正常单圈路径没有新增 MPI 归约，复用原有全局失败判定。
修复不会改 `qsave_d` 或重抽壁面随机数；已有临界节点位图继续用于检查点，不新增持久状态。

诊断内能改为先计算 `0.5*momentum*velocity` 再求和，避免先平方动量的中间溢出。
成功替换才计入修复次数。从 NaN/Inf 替换时，q 变化诊断记录新状态分量的幅值，不把它解释成有限的原值差。

`ASTR_GPU_CRASHFIX_EXPANDED` 的字段是：step、stage、传播轮数、全局扩展修复节点访问数、
最大索引搜索半径、各 rank 单点回退次数的最大值。

根 CMake 构建：`build_native_fp3_fp64_gpu`，NVHPC 26.1、FP64。
证据：`tests/gpu_validation/out/crashfix_expansion_20261025/`。

- `before.xml`：修改前，在有远处合法供体的实际 GPU 探针中复现退出码 92。
- `after2.xml`：8 项通过，包括 NP1/2/4 扩展恢复、全部无供体时非零退出、原单圈 CPU/GPU 顺序对照。
- `integration.xml`：7 项通过，包括 NP1/2/4 扩展恢复、MP 通量限制器关闭后的修复、有效 M12 轨迹开启/关闭修复逐值一致。
- `all.xml`：受影响测试文件全部 30 项通过、无跳过，含设备感知 MPI、CPU/GPU 单圈对照、实际修复历史 HDF5 往返、同拓扑续算及正常轨迹不变检查；运行约 73 秒。
- `pytest_final/*/expanded.log`：NP4 仅最后一个 rank 有合法状态时，经过 3 轮传播修好其他 rank 的 7803 个节点，最大搜索半径 17；缩放状态差 `4.44e-16`。
- `memcheck_np2.log`：真实扩展、跨 rank 传播及大数平均探针，每 rank Compute Sanitizer 零错误。
- `steep_replay/summary.json`：复用此前陡回流失败夹具的原始输入资源，仅开启 crashfix，MP 保正仍关闭。
  单 rank、NP2 x 分解均完成 100 步，dt=0.02；各累计 550 次节点修复访问，最大 CFL `0.0438178926899403`。
  末步最小密度 `0.04160405932678193`，最小内能密度约 `0.00348033294122051`，分解场差 `2.4646951146678475e-14`。

探针实现：`tests/gpu_validation/mp_ld_reconstruction_probe.cuf::check_expanding_crashfix`，
pytest：`tests/gpu_validation/test_mp_wall_crashfix.py`。
NVHPC 对大型探针过程出现内部编译错误；新增探针已拆成独立测试子程序，且仅该源文件使用
`-Mnofma -Mnovect -O0`。生产模块编译选项没有因此改变。

此前陡回流夹具在关闭 crashfix 时的负内能证据仍然有效。上述 100 步通过说明可恢复推进，
不能把它称为出口滤波已保正；该回放也不能独立证明新增扩展分支必要，后者由远处/远 rank 供体探针验证。

## 能力边界

- 这是邻域状态替换，不保证质量、动量和能量守恒，也不保证精确保留壁温或指定壁面速度。
- 搜索按索引距离，不是曲线网格上的物理距离最优化；跨 rank 可能经过已修复状态传播。
- 不承诺不同 MPI 分解下恢复轨迹逐值一致，同拓扑检查点继续保存 q、缓存及临界节点历史。
- 本轮新分支的 NP2/4 传播探针使用 x-slab，尚未单独验收扩展搜索在 y/z 分解或曲线壁面生产工况下的行为。
- 大片坏区的搜索可能昂贵；没有据本次结果宣称性能提升。
- 未运行 A800 生产任务、长时物理验收或 AIR5 测试；未操作 Git。
