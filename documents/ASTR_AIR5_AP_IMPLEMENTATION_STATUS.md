## AP3：在线线程块学习

`src_gpu/chemistry_launch_policy.F90` 已实现不依赖 CUDA/MPI 的调度状态，
由根 CMake 的 `chemistry_launch_policy_probe` 验证：五步固定预热、合法
候选掩码、轮转平衡采样、六轮中位数、长尾保留、原配置平局优先、截止
仅取完整轮次、零轮回退、五个上下文独立及启动重置。
证据为 `ap3_policy.log`；未调用上下文保留原配置，不因样本不足报错。

已通过 `chemistry_launch_tuning_gpu.cuf` 接入主程序，新增可选
`ASTR_AIR5_LAUNCH_TUNING=fixed|auto`，默认仍为 fixed。原化学块大小
128/32 选项保留；auto 以其为原配置，扩散原配置为 `(8,8,8)`。

- 每 rank 四组化学上下文和一组扩散上下文独立；只查询设备/核线程及
  资源合法性，不设占用率门槛，不增加调优计时或选优的 MPI 归约。
- 每次启动重置本地步计数，前五个完整步使用原配置；正常核调用的同
  stream 事件采集样本，不重复推进。事件对按上下文创建一次并复用。
- 收齐六轮后立即固定；启动后第 64 个完整步截止，仅用平衡完整轮次，
  零轮或不被调用的上下文保留原配置。短运行结束时明确记录尚在学习，
  不把未完成的样本当成已经选优。
- 原始样本同时记录候选、轮次及本次启动内步号，报告完整轮次中位数、
  全样本均值和范围，长尾不删除。无跨运行缓存或新增检查点字段。
- 保留已有显式核同步；本阶段没有实施异步通信或全设备等待的删除。

## AP4：第二阶段源项选择与工作区复用

首个候选已实现并通过局部及耦合数值检查。另完成下述诊断入口可选特化，
本轮不建立源项模式、补偿和历史开关的全组合模板；未将所有合法运行分派
都当成必须删除的分支。其余方向是否值得新增候选，仍须实际热点证据。

编译结果表明通用源项入口保留 pure/joint 两条路径及自己的 Jacobian 临时阵。
ROS-2 第一阶段 Jacobian 已在构造并分解线性系统后结束使用。现在将第二阶段
的 pure/joint 选择前移到 ROS-2 调用点：pure 直接调用原纯源项计算体；joint
调用原源项/Jacobian 计算体并复用第一阶段阵及进度率工作区。原通用源项接口
保留给其他消费者。不复制反应公式，不改变求值模式默认、Jacobian 有限检查、
选主元、积分容差、补偿或失败行为，也没有消除依赖真实状态的分支。

### 诊断入口可选特化

与 auto 组合时沿用四个化学逻辑上下文，候选合法性采用两入口资源交集，
不增加上下文或跨 rank 计时归约，不要求各 rank 选择相同优化入口。

数据依赖保持：通量核及其全局状态放行 → 当前方向打包 → 原 pair 传输 →
接收/散包；全部所需方向完成后才进入扩散限制系数和消费者。
现有字段交换只更新面 halo，不平均物理共享节点。打包读取物理节点，
接收和周期填充不修改物理节点，因此后续方向的发送数据可以独立预打包。

`packed-overlap` 在当前方向请求已提交后，通过原进展回调向另一个方向
的独立发送槽预打包，不嵌套发起第二组 MPI。每次调用重新准备当前通量，
不跨 RK 状态复用槽内数据；请求及 GPU 完成前不重用或释放缓冲。
当前 callback 使用一次创建、循环复用的私有 nonblocking stream，进展轮询
观察同一 stream，退出前显式等待该 stream 完成，不再等待全设备。
此前通量生产核和全局状态放行保证物理输入已经就绪，当前方向 MPI 与下一
方向打包使用不同槽；接收/散包仍在消费者之前完成。原单参数进展接口继续
观察默认 stream，其他调用者的依赖及显式同步不变。五轮完整步成本见 AP7。

私有缓冲按发生 MPI 交换的方向一次分配、循环复用，结束时释放。
host-staged 模式尊重原后端实际是否 pinned：页锁定槽使用 cudaHostAlloc/
cudaFreeHost，不逐步注册/释放；device-aware 不分配这些主机槽。
空邻居 MPI_PROC_NULL 的 D2H 已跳过，但缓冲仍提供合法地址供原接口使用。
这减少无用暂存，不改变有效网络负载或接收内容。

每方向额外设备字节数为
`4*hm*(横向物理节点数A)*(横向物理节点数B)*(27或33)*real_bytes`，
主机暂存模式另有同量级主机内存。这是面缓存，不是低内存承诺：长条网格
的大横截面仍会增加明显内存。原通用缓冲仍服务其他字段，没有被删除。

## 单位体系审计补充

当前核心路径未发现整场 SI→无量纲→SI 的反复转换：

- 非反应 GPU 按无量纲状态及方程系数推进。`solver::refcal` 在初始化设置
  Mach/Reynolds 相关常量；`q_to_primitive_kernel` 的 p/T 恢复属于 EOS，
  不是先恢复 SI 再归一化。
- AIR5 的 CPU/GPU 状态布局拒绝 `nondimen=t`，直接使用 SI 状态。
  机理生成器要求严格 SI 的 Arrhenius 与浓度基准，不在每点走 CGS/SI 往返。
- `rho_s/M_s` 是质量浓度到摩尔浓度的表示转换；`rho_s/rho` 是质量分数，
  不可当作冗余无量纲化删除。Jacobian 乘除是坐标变换，也不是单位往返。
- Sutherland 的温度比、Millikan–White 的压力比及现有输运公式固定因子属于
  相应模型。可检查派生常量、倒数、温度/压力公共量的前移，但没有证明它们
  全部成为运行时重复指令，不预先报告消除除法或加速。
- 基本场和检查点打包读取当前状态，不把无量纲输出自动变成 SI。分析文件时
  仍须遵守算例的单位定义。旧 Cantera 路径不计入本轮 AIR5 GPU 开销。

审计入口：`src/solver.F90::refcal`、`src/fludyna.F90::thermal/miucal`、
`src/chemistry_core.F90::air5_configure_runtime_layout`、
`src_gpu/chemistry_flow_state_gpu.cuf`、`src_gpu/chemistry_kinetics_gpu.cuf`、
`src_gpu/chemistry_relaxation_gpu.cuf`、`src_gpu/checkpoint_state_gpu.cuf`。
本补充未修改单位、参考量或相关计算路径。
