# 固定索引截面数值存档本地验收

日期：2026-10-29。分支：`feature/gpu_dev`。
基线提交：`063ee97d387b35a6d81d3bbb794f86868a128188`，本次改动尚未提交。
对应[专项计划](ASTR_INDEX_SLICE_ARCHIVE_EXTENSION_PLAN.md)SL0–SL8及必要公共控制前置。
结论：上述本地实现、接口/数值/续算/内存与成本交付已完成。
本报告不代表完整动态图片产品清单、A800部署或生产物理验收。

## 1. 交付接口

- 固定全局i/j/k索引，另两轴的闭区间整数范围。原网格节点不插值、不跳点，支持整面和矩形子区。
- JSONL逐产品选择基础字段、三维诊断、瞬时或实际已有的均值、步数或物理时间间隔。
  复用已登记事件/窗口，不新增统计或监测器。
- 完整步边界由根rank观察文件。原子发布后增改停用；仅调频不重置版本或上次成功输出。
  配置错误、已消费请求及资源停用分别处理，不因周期到达而自动重试。
- 每产品/定义版本/续算新段自带二维坐标、独立时刻HDF5及相对XDMF索引，无重复速度向量。
  均保留源精度和原单位体系；不压缩，不增加三维场归档。
- 内点和MPI接口采用独立六阶中心差分，物理边界采用七节点六阶单边/偏置模板，
  使用已有网格度量投影。临时邻域只读，不平均或修改求解器状态、halo或累计统计。
- 新`ASTRIR07`外层把原渲染控制段和动态清单控制分开保存。恢复以有效清单为准，
  不直接采用磁盘冲突配置，不重复恢复点成功帧；新段不引用旧运行文件。
  此前控制格式不再作为程序重启输入。

当前清单生产入口仅开放`slice/data/hdf5-xdmf`。既有显式图片配置仍保留，
不因开启数值截面而触发图片、流线、等值面或新的累计统计。

同字段需求可复用它，否则先释放再计算下一组，不建立按产品数量增长的整场缓存。

## 4. 本地中等M12成本

配置：96×48×32区间，NP=2（2×1×1），本地双RTX 4000 Ada，FP64，dt=0.02，10完整步。
关闭渲染、checkpoint、三维场和逐RK诊断快照，保留原标量监测。
每2步输出，另有首次0步，共6帧；计时窗口不含启动和0步初始输出。
固定种子/物理输入和原算法不变，未启用新监测或新的统计累积。

原始输入、日志、每rank分项计时、20ms资源采样及二维文件在`m12_cost_final/`，汇总为`summary.json`。

本规模以文件创建/元数据/写出为主要输出成本，诊断核与字段下载较小。
原始MPI条带记账是所有rank发送＋接收字节，不等于唯一网络发送量，且独立于表中的字段D2H。

不能直接相减当作产品附加主机内存，更不能把负差称为节省内存。

## 5. 修复及剩余边界

本轮修复均在新控制/输出实现内，没有改变CPU原物理边界、求解器格式、推进或统计采样定义。

1. NVHPC内部分配列表在调用方保留旧长度：改为一次分配索引槽并显式传递有效长度，修复MPI条带越界。
2. 设备`allocate(...,stat=...)`在实际OOM时仍直接退出：新私有缓冲改用可返回状态的`cudaMalloc`及明确匹配的`cudaFree`。
3. 不同长度字符串的`FINDLOC`未正确匹配，逻辑数组替代也在当前运行库未实现：新自适应绑定改用小表直接比较。
4. ParaView与用户h5py加载不同HDF5 ABI：普通Python准备原生NPZ参考，独立pvpython读XDMF，不禁用逐值对照。

尚未完成的上层方向不是本goal的通过条件：完整X2图片/探针/壁面产品热更新、移动网格、
任意物理平面数值插值、新平均量累计、GPU-aware私有截面条带及平台生产规模验收。
已有GPU紧凑M12统计沿z归约，未冒充任意k处的三维时间均值。AIR5当前统计缺少的Tv/Y均值仍拒绝。
旧grouped-slice编排与历史记录不再作为当前静态`slices`入口执行；相应旧文件的离线读取不等于程序重启兼容。

普通使用见[输入与工具说明](../scripts/output/INDEX_SLICE_ARCHIVES.md)和根`USER_GUIDE.md`。
全部Git暂存、提交、推送及平台作业均未执行。
